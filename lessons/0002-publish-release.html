PhotoCollect · Lesson 0002

发布一个经过验收的完整版本

本课完成一个具体结果：把当前验收通过的 PhotoCollect EXE 上传到群晖，生成下载页和版本清单，并发送更新通知。

当前 PhotoCollect 客户端还没有自动下载和退出替换功能。因此本课发布完成后，同事先通过局域网下载页手动更新；自动更新和增量包属于下一阶段。

发布前准备

  • 群晖 192.168.110.79 和两个容器保持运行。
  • Windows 能访问 \\192.168.110.79\PhotoCollectUpdates\releases。
  • Windows 已安装 PowerShell 7；一键入口不会降级使用 Windows PowerShell 5.1。
  • 当前 EXE 已通过版本、功能和 OCR 验收。
  • publisher 令牌保存在密码管理器中，没有出现在脚本或聊天记录里。

执行发布

1

复制 publisher 令牌

只复制令牌本身，不要把它粘贴到脚本、文件名或聊天窗口。发布脚本读取后会立即清空剪贴板。

2

双击一键发布入口

运行项目根目录的：

一键发布到群晖.bat

脚本自动读取 con.py 的版本号，寻找同版本最新验收报告，并重新计算 EXE 的大小和 SHA-256。

3

核对并确认

屏幕会显示版本、验收报告、来源 EXE、大小、SHA-256、群晖目录和下载地址。全部正确后输入：

PUBLISH

其他输入会安全取消，不会写入群晖。

4

等待五项完成

[1/5] 上传并核对不可变版本文件
[2/5] 准备稳定下载首页和健康文件
[3/5] 从 HTTP 完整下载并复核大小、SHA-256
[4/5] 原子提交 latest.json 发布指针
[5/5] 推送 release.ready 通知

latest.json 是最后提交的发布指针。版本化 EXE 经 HTTP 完整下载并重新核对哈希后，才会更新该指针并推送通知，避免同事收到指向半成品的消息。

发布后得到什么

产物作用
PhotoCollect-v5.15.2.exe不可变的版本化完整安装文件
PhotoCollect-v5.15.2.json该版本的固定清单
latest.json当前作为下载页的数据源；未来也供客户端检查最新版
index.html稳定下载页，运行时读取 latest.json 展示最新版本
health.txt静态文件服务健康检查

验收

完整版本发布链路已经掌握。下一阶段可以接入客户端自动检查、下载校验和安全替换。

可信依据

  • Microsoft：Get-FileHash，用于核对文件完整性。
  • ntfy：Sending messages，用于发布带认证的更新通知。

哪里看不懂或出现错误，直接把不含令牌的输出发给 Codex，不要猜着继续。
