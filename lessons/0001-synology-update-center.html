PhotoCollect · Lesson 0001

在群晖部署局域网更新中心

完成后，群晖会持续提供更新文件和实时通知通道；Windows 电脑负责构建并发布，同事电脑只负责安全下载。

先明确边界：本课只搭建群晖服务器基础。当前桌面版 v5.15.2 尚未接入自动更新，不能因为容器启动成功就认为客户端已经会更新。客户端、增量包和一键发布需要在后续版本接入。

最终结构

Windows 发布电脑
    │  SMB 上传完整包、增量包、latest.json
    ▼
群晖
    ├─ NGINX :18080  只读提供更新文件
    └─ ntfy  :18081  推送“有新版本，请检查”
                           │
                           ▼
                    PhotoCollect 客户端

开始前准备

  • 确认群晖已安装 Container Manager。
  • 群晖固定局域网 IP 已确认为 192.168.110.79。
  • 确认实际卷名。多数机器是 /volume1，也可能是 /volume2。
  • 确认端口 18080 和 18081 未被其他程序占用。

第一部分：准备目录

1

创建共享文件夹

打开 DSM 的控制面板 → 共享文件夹 → 新增，名称填：

PhotoCollectUpdates

建议开启回收站。管理员拥有读写权限；普通同事不需要 SMB 写入权限。

2

创建两个子目录

打开 File Station，在共享文件夹中创建：

/volume1/PhotoCollectUpdates/releases
/volume1/PhotoCollectUpdates/ntfy

releases 存更新包，容器只读；ntfy 存通知缓存、用户和权限数据库，容器必须可写。

3

放一个测试文件

在 Windows 新建 health.txt，内容只有 ok，上传到 releases。稍后用它验证静态文件服务。

第二部分：创建 Container Manager 项目

4

新建项目

打开Container Manager → 项目 → 新增：

  • 项目名称：photocollect-update-center
  • 路径：选择一个项目工作目录，例如 /volume1/docker/photocollect-update-center
  • 来源：选择“使用编辑器创建 docker-compose.yml”
项目目录和更新数据目录不是同一个目录。 项目目录只保存 Compose；下面的卷挂载仍应使用 /volume1/PhotoCollectUpdates/releases 和 /volume1/PhotoCollectUpdates/ntfy。不要因为项目放在 /volume1/docker，就自动给数据路径也加上 /docker。

群晖官方也支持上传现成 Compose 文件。查看官方步骤。

5

粘贴 Compose

下面已经使用当前群晖地址 192.168.110.79 和数据卷 /volume1：

name: photocollect-update-center

services:
  files:
    image: nginx:1.29.8-alpine
    container_name: photocollect-files
    restart: unless-stopped
    ports:
      - "18080:80"
    volumes:
      - /volume1/PhotoCollectUpdates/releases:/usr/share/nginx/html:ro

  notify:
    image: binwiederhier/ntfy:v2.26.3
    container_name: photocollect-notify
    restart: unless-stopped
    command:
      - serve
    environment:
      TZ: Asia/Shanghai
      NTFY_BASE_URL: http://192.168.110.79:18081
      NTFY_CACHE_FILE: /var/lib/ntfy/cache.db
      NTFY_AUTH_FILE: /var/lib/ntfy/auth.db
      NTFY_AUTH_DEFAULT_ACCESS: deny-all
      NTFY_ENABLE_LOGIN: "true"
    ports:
      - "18081:80"
    volumes:
      - /volume1/PhotoCollectUpdates/ntfy:/var/lib/ntfy
镜像版本已固定，避免某天自动拉到不兼容的 latest。以后升级容器时，先备份 ntfy 目录，再显式修改版本号。
6

构建并启动

确认摘要后勾选“完成后启动项目”。首次需要下载镜像，等待两个容器都显示 Running。

如果持续重启，打开项目 → 详情 → 日志。最常见原因是卷名写错、目录不存在、ntfy 目录无写权限或端口被占用。

第三部分：创建推送账号与权限

ntfy 默认允许匿名读写。本 Compose 已设置 deny-all；没有创建用户前，任何推送请求被拒绝是正常且安全的。
7

进入通知容器终端

打开Container Manager → 容器 → photocollect-notify → 详情 → 终端，点击“新增”旁的下拉按钮，用命令 /bin/sh 创建终端。不要使用默认的 /bin/bash；ntfy 的 Alpine 精简镜像没有 bash。

先查看已有用户，再只创建缺少的账号：

ntfy user list
ntfy user add publisher
ntfy user add client
ntfy access publisher photocollect-updates write-only
ntfy access client photocollect-updates read-only
ntfy access

如果 ntfy user list 已显示某个账号，就跳过对应的 user add，避免重复。新增账号时会要求输入密码。publisher 只能发通知，client 只能收通知。

8

生成两个令牌

ntfy token add --label="PhotoCollect publisher" publisher
ntfy token add --label="PhotoCollect client" client
ntfy token list publisher
ntfy token list client

只有 token add ... 用户名 创建并且能在该用户名的列表中看到的令牌才可用于认证；token generate 只产生随机字符串，不会自动绑定账号。立即把返回的两个 tk_... 分开保存在密码管理器。发布端只保存 publisher 令牌；客户端只保存 client 令牌。不要把令牌写进公开的 Compose、命令提示文字或截图。

第四部分：逐项验证

9

验证文件服务器

在同一局域网的 Windows 浏览器打开：

http://192.168.110.79:18080/health.txt

页面应显示 ok。也可以运行：

Invoke-WebRequest "http://192.168.110.79:18080/health.txt" |
  Select-Object StatusCode, Content
10

验证通知服务健康

Invoke-RestMethod "http://192.168.110.79:18081/v1/health"

正确结果应包含：

{"healthy":true}
11

验证实时推送

先在群晖终端复制 client 令牌，再打开第一个 PowerShell。下面的命令从剪贴板读取令牌、去除首尾空白并立即清空剪贴板，不需要把令牌写进命令：

$clientToken = (Get-Clipboard -Raw).Trim()
Set-Clipboard -Value ""
[pscustomobject]@{
  PrefixOK = $clientToken.StartsWith("tk_")
  Length   = $clientToken.Length
}
curl.exe -sS -o NUL -w "HTTP %{http_code}`n" `
  -H "Authorization: Bearer $clientToken" `
  "http://192.168.110.79:18081/photocollect-updates/json?poll=1"

# 上一条返回 HTTP 200 后，再开始持续订阅
curl.exe -N `
  -H "Authorization: Bearer $clientToken" `
  "http://192.168.110.79:18081/photocollect-updates/json"

复制 publisher 令牌，再打开第二个 PowerShell：

$publisherToken = (Get-Clipboard -Raw).Trim()
Set-Clipboard -Value ""
[pscustomobject]@{
  PrefixOK = $publisherToken.StartsWith("tk_")
  Length   = $publisherToken.Length
}
curl.exe -sS -o NUL -w "HTTP %{http_code}`n" `
  -X POST `
  -H "Authorization: Bearer $publisherToken" `
  -H "Content-Type: text/plain; charset=utf-8" `
  --data-binary "release.ready test-001" `
  "http://192.168.110.79:18081/photocollect-updates"

第二个窗口应返回 HTTP 200；第一个窗口应立即出现一行 JSON，其中包含 "event":"message" 和 "message":"release.ready test-001"。

第五部分：限制为局域网访问

进入控制面板 → 安全性 → 防火墙。添加规则，仅允许公司局域网网段访问 TCP 18080 和 18081，例如 192.168.1.0/24。把允许规则放在拒绝规则之前。

  • 不要在路由器上做公网端口转发。
  • 不要给 Everyone 共享目录写权限。
  • 如果公司有访客 Wi-Fi，应确保访客网不能访问这两个端口。
  • 正式使用 Basic Auth 或令牌前，建议在 DSM 反向代理中加 HTTPS；HTTP 中的令牌不会被加密。

验收清单

群晖更新中心基础已完成。下一步先发布一个经过验收的完整版本，再接入客户端自动检查、后台下载和退出后替换。
